# Document survey, 7 October 2026

What's in the phase 1 archive (DSS + Services Australia main disclosure logs), to size phase 2.
Per-document results: `data/survey/survey_docs.csv` (gitignored). Script: run from the session
scratchpad (`survey.py`, pdfinfo + `pdftotext -layout`, first 300 pages).

## Method

- Scanned = under 100 characters of extractable text per page.
- Table line = a line whose cells (split on 2+ spaces) include at least 2 numeric cells
  (digits, commas, decimals, %, $).
- Has numeric tables = 10+ table lines; some numbers = 3-9.
- Anchor check: "Age Pension recipients outside Australia" (FOI LEX 56898, a 2-column
  country table) was missed at a 3-numeric-cell threshold; caught at 2 (550 table lines).

## Results

Documents per class (count of downloaded documents):

| Class | DSS | Services Australia | Total |
|---|---|---|---|
| PDF with numeric tables | 43 | 6 | 49 |
| PDF with some numbers | 16 | 2 | 18 |
| Scanned / image-only PDF | 41 | 31 | 72 |
| Text PDF, no tables | 113 | 105 | 218 |
| Word | 1 | 0 | 1 |
| **Total** | **214** | **144** | **358** |

- About 1 in 7 documents has machine-readable statistical tables; another 1 in 5 is scanned and
  needs OCR, and some of those are statistical ("Statistical data on student assistance
  recipients", 97 and 53 pages, scanned).
- The rest is correspondence, briefs, contracts and policy documents: still worth indexing for
  text search, not for tables.
- Table-bearing examples: welfare recipients by payment type (16/17-030), DSP recipients since
  1992 by state (FOI 19/20-073), unemployment benefit expenditure (16/17-018), Age Pension
  recipients by country (FOI LEX 56898), Centrepay deductions (LEX 89516), Senate Estimates and
  Question Time briefs.
- Layout gotcha: `pdftotext -layout` misaligns rows in sparse tables (FOI LEX 56898 shows
  blank rows interleaved with country rows, shifting values one row). pdfplumber got it right
  (checked against the rendered page: Albania 6, Canada 1,074, Egypt 48). Use pdfplumber, not pdftotext, for tables.

## Tooling on this machine

- Available: poppler (`pdftotext`, `pdfinfo`), R `pdftools`.
- pdfplumber 0.11.10 installed 7 October 2026 (pip --user). Not installed: Tesseract OCR, camelot, tabulizer.
- Phase 2 needs OCR (Tesseract or OCRmyPDF) for the 72 scanned documents.

## Phase 2 prototype: pdfplumber table extraction (7 October 2026)

`scripts/extract_tables.py`, default (ruled-line) strategy, all 49 "has numeric tables" documents:
6,983 pages in 691 seconds, 0 errors. Output: `data/extract/` (one CSV per table + `tables_index.csv`).

Tables found, by type (count):

| Type | Count |
|---|---|
| Numeric (2+ cols/rows, ≤60% empty, ≥30% numeric cells) | 1,038 |
| Mixed | 128 |
| Text-only grid | 1,039 |
| Mostly empty (>60% blank) | 1,643 |
| Tiny (<2 rows or cols) | 2,729 |

- 33 of 49 documents yield at least one numeric table. Of the other 16: 12 have unruled tables
  (no gridlines) that the default strategy misses. The text strategy finds their numbers but
  splits words mid-token ("Count of applic | ants"), so unruled tables need a second method.
- Checked against rendered pages, all exact: Age Pension by country (FOI LEX 56898 p1),
  payment type by country of birth (16/17-030 p1), Newstart partial capacity by state 2007-2019
  (FOI 19/20-073 p29, all 13 years). Centrepay deductions (LEX 89516 p2): CSV structure looks
  right, not compared to the page image.
- Multi-line headers come through as embedded newlines; title blocks become a first "row".
  Clean-up needed before publishing.
